# สถาปัตยกรรมระบบร้านขายผัก [ชื่อร้าน]

เอกสารนี้สรุปการตัดสินใจที่อนุมัติแล้ว ใช้เป็นแนวทางตอนพัฒนา

---

## การตัดสินใจที่อนุมัติแล้ว

| หัวข้อ | ที่เลือก | เหตุผล |
|---|---|---|
| หน้าเว็บ | Next.js 15 (App Router) + Tailwind CSS | Mobile-first, คำนวณเงินฝั่งเซิร์ฟเวอร์ได้ |
| ฐานข้อมูล | Cloud Firestore แพลนฟรี (Spark) | ไม่ต้องผูกบัตร ไม่มีการพักโปรเจกต์ |
| เก็บรูปสินค้า | บีบอัดเป็น WebP แล้วเก็บใน Firestore | 0 บาท ไม่ต้องผูกบัตร (Firebase Storage ต้องขึ้นแพลน Blaze) |
| นำขึ้นออนไลน์ | Netlify แพลนฟรี | ฟรีและอนุญาตให้ใช้เชิงพาณิชย์ (Vercel Hobby ห้ามใช้เชิงพาณิชย์) |
| ล็อกอินหลังบ้าน | PIN 6 หลัก | ง่ายที่สุดสำหรับเจ้าของร้าน |
| ค่าส่ง | ไม่มีค่าส่ง | เก็บช่องไว้ในฐานข้อมูลเผื่อเปลี่ยนใจภายหลัง |
| รอบจัดส่ง | เจ้าของสร้างรอบล่วงหน้า ลูกค้าเลือกรอบตอนสั่ง | วางแผนส่งเป็นกลุ่มตามหมู่บ้านได้ |

ค่าใช้จ่ายรวม: **0 บาท/เดือน** — จ่ายเฉพาะค่าโดเมนตอนพร้อมเปิดจริง

## ภาพรวมระบบ

```
มือถือลูกค้า / มือถือเจ้าของร้าน
        │  HTTPS
        ▼
┌───────────────────────────────────────┐
│  Next.js (รันบน Netlify)               │
│  • หน้าเว็บ (Server Components)         │
│  • Server Actions / Route Handlers     │ ← คำนวณเงินทุกบาทที่นี่
│  • middleware.ts กันคนนอกเข้า /admin    │
└───────────────┬───────────────────────┘
                │ Firebase Admin SDK
                ▼
┌───────────────────────────────────────┐
│  Cloud Firestore (Spark)              │
│  อ่าน 50,000 / เขียน 20,000 ต่อวัน      │
│  พื้นที่ 1GB (รวมรูปสินค้าที่บีบแล้ว)      │
└───────────────────────────────────────┘
```

### หลักความปลอดภัย 4 ข้อ

1. **เบราว์เซอร์คุยกับ Firestore ตรงๆ ไม่ได้** — Security Rules ตั้งเป็น `allow read, write: if false`
   ทุกอย่างผ่านเซิร์ฟเวอร์ Next.js เท่านั้น
2. **ราคาคำนวณฝั่งเซิร์ฟเวอร์เสมอ** — หน้าเว็บส่งมาแค่ `productId + unitId + จำนวน`
   เซิร์ฟเวอร์ดึงราคาปัจจุบันมาคูณเอง แล้วบันทึกราคานั้นแนบไว้ในออเดอร์
3. **PIN เก็บเป็น hash (bcrypt)** — session เป็น cookie HttpOnly อายุ 30 วัน
   กดผิด 5 ครั้งล็อก 15 นาที
4. **กันกดสั่งซ้ำ** — ทุกออเดอร์มี idempotency key กดซ้ำได้ออเดอร์เดิม ไม่สร้างใบใหม่

## โครงสร้างฐานข้อมูล (Firestore)

```
settings/shop              ชื่อร้าน โลโก้ เบอร์ ประกาศ เวลาปิดรับ ค่าส่ง(0)
                           การแสดงของหมด(สีเทา/ซ่อน) เปิด-ปิดร้าน
admin_users/{id}           ชื่อ pinHash บทบาท ใช้งานอยู่ไหม ครั้งที่กดผิด ล็อกถึงเมื่อไหร่

categories/{id}            ชื่อหมวด ไอคอน ลำดับ เปิดใช้งาน
products/{id}
  ├ name categoryId description ลำดับ เปิด/ปิดการขาย ลบแล้วไหม
  ├ thumbData              รูปย่อ 300px WebP (~12KB) ใช้ในการ์ดหน้าแรก
  ├ searchTerms[]          คำค้นภาษาไทย
  └ units[]                { id, label, ประเภท, price, ขั้นการกด,
                             เป็นหน่วยหลักไหม, เปิดขายไหม, ปรับตามน้ำหนักจริงได้ไหม }
product_images/{productId} รูปเต็ม 800px WebP (~50KB) แยกไว้ไม่ให้หน้าแรกโหลดหนัก
price_history/{id}         สินค้า หน่วย ราคาเดิม→ราคาใหม่ ใครแก้ เมื่อไหร่ รหัสชุดการแก้

zones/{id}                 หมู่บ้าน/โซน: ชื่อ ลำดับ ค่าส่ง(0) หมายเหตุ เปิดใช้งาน
delivery_rounds/{id}       ชื่อรอบ โซน วันที่ส่ง ช่วงเวลา ปิดรับเมื่อไหร่ จำนวนสูงสุด
                           สถานะ(เปิดรับ/ปิดรับ/กำลังส่ง/จบรอบ) ให้ลูกค้าเห็นไหม
                           สรุปปิดรอบ{ส่งสำเร็จ ส่งไม่สำเร็จ เก็บเงินได้ ค้าง}

customers/{เบอร์โทร}        ชื่อ ที่อยู่ โซน จำนวนครั้งที่สั่ง ยอดสะสม
                           ยอดค้างชำระ สั่งล่าสุดเมื่อไหร่ หมายเหตุ

orders/{id}
  ├ orderNo                เลขที่ออเดอร์ที่ลูกค้าเห็น เช่น 260807-001
  ├ ข้อมูลลูกค้า ณ ตอนสั่ง   ชื่อ/เบอร์/ที่อยู่/โซน (คัดลอกเก็บไว้ ไม่อ้างอิงสด)
  ├ roundId                รอบส่งที่ลูกค้าเลือก
  ├ items[]                { สินค้า หน่วย ราคาต่อหน่วย จำนวนที่สั่ง ยอดรายการ
  │                          จำนวนจริงที่ชั่งได้ ยอดจริง }
  ├ ยอดรวม → ยอดหลังปรับน้ำหนักจริง
  ├ สถานะจัดส่ง             รับออเดอร์ / กำลังจัดของ / กำลังจัดส่ง / ส่งสำเร็จ /
  │                          ส่งไม่สำเร็จ(เหตุผล) / ยกเลิก(เหตุผล)
  ├ สถานะเก็บเงิน           ยังไม่เก็บ / เก็บแล้ว / ค้างชำระ
  ├ ยอดที่เก็บได้จริง วิธีชำระ(เงินสด/โอน) รูปสลิป(บีบแล้ว)
  └ events/{id}            ประวัติทุกการเปลี่ยนแปลง "แก้จากเท่าไหร่เป็นเท่าไหร่ ใครแก้ เมื่อไหร่"

counters/orderNo           ตัวนับเลขออเดอร์ (ใช้ transaction กันเลขชนกัน)
idempotency/{key}          กันกดสั่งซ้ำ
daily_stats/{2026-08-07}   สรุปยอดรายวันสำเร็จรูป ให้หน้ารายงานเปิดเร็วและประหยัดโควต้าอ่าน
```

### เผื่ออนาคตไว้แล้ว (ยังไม่เขียนโค้ด)

- `customers.lineUserId` — ต่อแจ้งเตือนผ่าน LINE
- ออเดอร์เก็บรายการครบพอที่จะกด "สั่งซ้ำ" ได้ทันที
- `orders.discountTotal` + `orders.promotionId` — โปรโมชั่นและส่วนลด
- `customers.points` + `customers.tier` — ระบบสมาชิกสะสมแต้ม
- `orders.paymentRef` + `orders.paymentProvider` — ชำระเงินออนไลน์

## หน้าเว็บทั้งหมด

**ฝั่งลูกค้า**

| เส้นทาง | หน้า |
|---|---|
| `/` | เลือกสินค้า (หมวดหมู่ + ค้นหา + แถบยอดรวมลอยด้านล่าง) |
| `/cart` | ตะกร้า |
| `/checkout` | กรอกชื่อ-เบอร์-ที่อยู่ เลือกโซนและรอบส่ง |
| `/order/[เลขที่]` | ยืนยันสำเร็จ พร้อมหมายเลขออเดอร์ |
| `/track` | ติดตามสถานะด้วยเบอร์โทรหรือหมายเลขออเดอร์ |

**ฝั่งเจ้าของร้าน**

| เส้นทาง | หน้า |
|---|---|
| `/admin/login` | กด PIN |
| `/admin` | หน้าแรก แจ้งเตือนออเดอร์ใหม่ |
| `/admin/prices` | **แก้ราคาประจำวัน หน้าเดียวจบ** (ใช้ทุกวัน) |
| `/admin/products` | เพิ่ม/แก้/ลบสินค้า อัพโหลดรูป |
| `/admin/orders` | ออเดอร์ทั้งหมด แยกวันและสถานะ |
| `/admin/rounds` | รอบจัดส่ง + ใบรายการส่งของ |
| `/admin/debts` | ใครยังค้างเงิน ยอดค้างรวม |
| `/admin/customers` | ทะเบียนลูกค้า |
| `/admin/reports` | รายงานยอดขาย สินค้าขายดี |
| `/admin/settings` | ตั้งค่าร้าน โซน เวลาปิดรับ ประกาศ เปลี่ยน PIN |

## การจัดการรูปภาพ

เจ้าของถ่ายจากมือถือ → บีบอัดในเบราว์เซอร์ก่อนอัปโหลด (ไม่ต้องรอเน็ตอัปโหลดไฟล์ใหญ่)

1. ย่อด้านกว้างเหลือ 800px แปลงเป็น WebP คุณภาพ 0.75 → ประมาณ 40–60KB
2. สร้างรูปย่อ 300px อีกใบ → ประมาณ 12KB ใช้แสดงในการ์ดหน้าแรก
3. เก็บทั้งสองใบใน Firestore (รูปย่ออยู่ในเอกสารสินค้า รูปเต็มแยกเอกสาร)

รูปผัก 100 ชนิดใช้พื้นที่รวมไม่ถึง 10MB จากโควต้าฟรี 1GB
