# สถาปัตยกรรมระบบร้านขายผัก [ชื่อร้าน]

เอกสารนี้สรุปการตัดสินใจที่อนุมัติแล้ว ใช้เป็นแนวทางตอนพัฒนา

---

## การตัดสินใจที่อนุมัติแล้ว

| หัวข้อ | ที่เลือก | เหตุผล |
|---|---|---|
| หน้าเว็บ | Next.js 15 (App Router) + Tailwind CSS | Mobile-first, คำนวณเงินฝั่งเซิร์ฟเวอร์ได้ |
| ฐานข้อมูล | Cloud Firestore แพลนฟรี (Spark) | ไม่ต้องผูกบัตร ไม่มีการพักโปรเจกต์ |
| เก็บรูปสินค้า | บีบอัดเป็น WebP แล้วเก็บใน Firestore | 0 บาท ไม่ต้องผูกบัตร (Firebase Storage ต้องขึ้นแพลน Blaze) |
| นำขึ้นออนไลน์ | Netlify แพลนฟรี | ฟรีและอนุญาตให้ใช้เชิงพาณิชย์ (Vercel Hobby ห้ามใช้เชิงพาณิชย์) |
| ล็อกอินหลังบ้าน | PIN 6 หลัก | ง่ายที่สุดสำหรับเจ้าของร้าน |
| ค่าส่ง | ไม่มีค่าส่ง | เก็บช่องไว้ในฐานข้อมูลเผื่อเปลี่ยนใจภายหลัง |
| รอบจัดส่ง | เจ้าของสร้างรอบล่วงหน้า **สร้างรอบ = ได้ลิงก์ทันที** | ส่งลิงก์เข้ากลุ่มไลน์ ลูกค้ากดสั่งได้เลยไม่ต้องเลือกวัน |
| กลุ่ม | แต่ละกลุ่มมีรายการสินค้าและราคาของตัวเอง | กลุ่ม BNI Icon กับหมู่บ้าน A ขายไม่เหมือนกัน ราคาอาจต่างกัน |
| ใบพิมพ์ | ฟอร์มกระดาษคาร์บอนกว้าง 80 มม. 3 แบบ | ใช้กับเครื่องพิมพ์สลิปที่ร้านมีอยู่ |
| แจ้งเตือนออเดอร์ | LINE Messaging API + การแจ้งเตือนบนเว็บ | LINE Notify ปิดบริการแล้ว ต้องใช้ Messaging API แทน |

ค่าใช้จ่ายรวม: **0 บาท/เดือน** — จ่ายเฉพาะค่าโดเมนตอนพร้อมเปิดจริง

## ภาพรวมระบบ

```
มือถือลูกค้า / มือถือเจ้าของร้าน
        │  HTTPS
        ▼
┌───────────────────────────────────────┐
│  Next.js (รันบน Netlify)               │
│  • หน้าเว็บ (Server Components)         │
│  • Server Actions / Route Handlers     │ ← คำนวณเงินทุกบาทที่นี่
│  • middleware.ts กันคนนอกเข้า /admin    │
└───────────────┬───────────────────────┘
                │ Firebase Admin SDK
                ▼
┌───────────────────────────────────────┐
│  Cloud Firestore (Spark)              │
│  อ่าน 50,000 / เขียน 20,000 ต่อวัน      │
│  พื้นที่ 1GB (รวมรูปสินค้าที่บีบแล้ว)      │
└───────────────────────────────────────┘
```

### หลักความปลอดภัย 4 ข้อ

1. **เบราว์เซอร์คุยกับ Firestore ตรงๆ ไม่ได้** — Security Rules ตั้งเป็น `allow read, write: if false`
   ทุกอย่างผ่านเซิร์ฟเวอร์ Next.js เท่านั้น
2. **ราคาคำนวณฝั่งเซิร์ฟเวอร์เสมอ** — หน้าเว็บส่งมาแค่ `productId + unitId + จำนวน`
   เซิร์ฟเวอร์ดึงราคาปัจจุบันมาคูณเอง แล้วบันทึกราคานั้นแนบไว้ในออเดอร์
3. **PIN เก็บเป็น hash (bcrypt)** — session เป็น cookie HttpOnly อายุ 30 วัน
   กดผิด 5 ครั้งล็อก 15 นาที
4. **กันกดสั่งซ้ำ** — ทุกออเดอร์มี idempotency key กดซ้ำได้ออเดอร์เดิม ไม่สร้างใบใหม่

### เผื่ออนาคตไว้แล้ว (ยังไม่เขียนโค้ด)

- `customers.lineUserId` — ต่อแจ้งเตือนผ่าน LINE
- ออเดอร์เก็บรายการครบพอที่จะกด "สั่งซ้ำ" ได้ทันที
- `orders.discountTotal` + `orders.promotionId` — โปรโมชั่นและส่วนลด
- `customers.points` + `customers.tier` — ระบบสมาชิกสะสมแต้ม
- `orders.paymentRef` + `orders.paymentProvider` — ชำระเงินออนไลน์

## ลิงก์สั่งซื้อรายรอบ และกลุ่ม

### แนวคิด

**สร้างรอบส่ง 1 ครั้ง = ได้ลิงก์ 1 อัน** เอาไปแปะในกลุ่มไลน์ได้เลย
คนที่กดลิงก์เข้ามาจะเห็นเฉพาะสินค้าของกลุ่มนั้น ในราคาของกลุ่มนั้น
และ **ไม่ต้องเลือกวันรับของ** เพราะลิงก์ล็อกวันไว้ให้แล้ว

| ลูกค้าเข้ามาทาง | เห็นสินค้า | เลือกวันส่ง | กรอกที่อยู่ |
|---|---|---|---|
| หน้าเว็บหลัก `/` | ทุกอย่างที่เปิดขาย ราคากลาง | ต้องเลือกรอบเอง | ต้องกรอก |
| ลิงก์กลุ่ม `/r/{slug}` แบบกรอกที่อยู่ | เฉพาะของกลุ่ม ราคาของกลุ่ม | ล็อกไว้แล้ว | ต้องกรอก |
| ลิงก์กลุ่ม `/r/{slug}` แบบส่งจุดเดียว | เฉพาะของกลุ่ม ราคาของกลุ่ม | ล็อกไว้แล้ว | **ไม่ต้องกรอก** |

แบบสุดท้ายใช้กับกรณีส่งที่เดียวกันทั้งกลุ่ม เช่นส่งที่อาคาร BNI Icon
ลูกค้ากรอกแค่ **ชื่อกับเบอร์** เพื่อให้รู้ว่าถุงไหนของใคร ที่อยู่มาจากที่เจ้าของตั้งไว้ในกลุ่ม

### ราคา — ตั้งครั้งเดียวหรือแยกรายกลุ่มก็ได้

ราคามี 2 ชั้น ระบบเลือกให้อัตโนมัติ

1. **ราคากลาง** เก็บใน `products.units[].price` แก้ในหน้าแก้ราคาประจำวัน
   แก้ทีเดียวมีผลกับทุกลิงก์
2. **ราคาเฉพาะกลุ่ม** เก็บใน `groups.prices` เฉพาะตัวที่เจ้าของตั้งทับไว้

```
ราคาที่ลูกค้าเห็น = groups.prices["สินค้า|หน่วย"]  ถ้าไม่มี → products.units[].price
```

ในหน้าแก้ราคาประจำวันมีปุ่มเลือกด้านบนว่ากำลังแก้ของใคร
เลือกกลุ่มแล้วแต่ละช่องจะบอกว่า *ใช้ราคากลาง* หรือ *ราคาเฉพาะกลุ่ม*
สลับไปมาได้ด้วยปุ่มเดียว — กด "กลับไปใช้ราคากลาง" แล้วราคานั้นจะขยับตามราคากลางเองทุกวัน

### ช่อง "อื่นๆ" — ของที่ไม่มีในรายการ

ลูกค้าพิมพ์เอง เช่น "มะเขือเทศราชินี 1 กก." โดยยังไม่มีราคา

```
ลูกค้าพิมพ์ของที่อยากได้ → เข้าตะกร้าแบบไม่มีราคา ไม่รวมในยอด
   └─ กดสั่งซื้อได้ตามปกติ → ออเดอร์สถานะ "รอยืนยันราคา"
        └─ เจ้าของเปิดออเดอร์ ใส่ราคา หรือกด "ไม่มีของ"
             └─ ระบบคิดยอดใหม่ + แจ้งลูกค้า → สถานะเปลี่ยนเป็น "รับออเดอร์แล้ว"
```

- ยอดรวมที่ลูกค้าเห็นตอนสั่งจะเขียนกำกับว่า **"ยังไม่รวมของที่รอร้านยืนยันราคา"**
- ออเดอร์ที่ยังรอยืนยันจะขึ้นป้ายสีส้มเด่นในหน้าออเดอร์และในหน้ากลุ่ม
- ปิดช่องนี้รายกลุ่มได้ ถ้ากลุ่มไหนไม่อยากให้พิมพ์ขอเพิ่ม

## แจ้งเตือนออเดอร์ใหม่เข้า LINE

### ข้อมูลที่ตรวจสอบแล้ว

- **LINE Notify ปิดบริการถาวรตั้งแต่ 31 มีนาคม 2568** ใช้ไม่ได้แล้ว ต้องใช้ LINE Messaging API แทน
- LINE Official Account **แพลนฟรีของไทยได้ 500 ข้อความ/เดือน**
- ข้อความนับ **รายคนที่ส่งถึง** ส่งเข้ากลุ่ม 3 คน = นับ 3 ข้อความ
- **ข้อความตอบกลับ (Reply) ไม่นับโควต้าและไม่จำกัดจำนวน** แต่ส่งได้เฉพาะตอนที่มีคนทักเข้ามาก่อน

### วิธีออกแบบให้อยู่ในโควต้าฟรี

1. **ส่งเฉพาะเรื่องที่จำเป็น** — ค่าเริ่มต้นแจ้งแค่ "ออเดอร์ใหม่" 1 ข้อความต่อ 1 ออเดอร์
   ส่งถึงเจ้าของคนเดียว 500 ข้อความ/เดือน ≈ **รับได้ 16 ออเดอร์/วัน**
2. **โหมดรวมส่ง** — ถ้าออเดอร์เยอะขึ้น สลับเป็นรวมแจ้งทุก 30 นาที
   ("มี 4 ออเดอร์ใหม่ รวม 1,240 บาท") ใช้แค่ ~30 ข้อความ/เดือน
3. **เช็กยอดเองได้ฟรีไม่จำกัด** — เจ้าของพิมพ์ `ยอดวันนี้` หรือ `ค้างเงิน` ในแชท
   ระบบตอบกลับด้วย Reply API ซึ่งไม่กินโควต้าเลย
4. **การแจ้งเตือนบนเว็บเป็นตัวหลัก** — เพิ่มเว็บลงหน้าจอมือถือ (PWA) แล้วเด้งแจ้งเตือนได้
   แม้ปิดเว็บอยู่ ฟรีและไม่จำกัดจำนวน ใช้คู่กับ LINE เป็นตัวสำรอง
5. **หน้าตั้งค่าแสดงโควต้าที่เหลือ** — พร้อมเตือนเมื่อใช้ไปเกิน 80%

หากในอนาคตร้านโตจนเกิน 500 ข้อความ/เดือนจริงๆ แพลนถัดไปของ LINE เริ่มที่ประมาณ
1,500 บาท/เดือน — **จะแจ้งขออนุมัติก่อนเสมอ ไม่ผูกบัตรให้เอง**

### การทำงาน

```
ลูกค้ากดยืนยันสั่งซื้อ
   └─ เซิร์ฟเวอร์บันทึกออเดอร์ (transaction)
        └─ สร้างเอกสารใน notifications/ สถานะ "รอส่ง"
             ├─ ส่งเข้า LINE ผ่าน Messaging API (push)
             └─ ส่งการแจ้งเตือนบนเว็บไปยังมือถือที่ลงทะเบียนไว้
                  └─ ส่งไม่สำเร็จ → ลองใหม่อัตโนมัติ 3 ครั้ง แล้วบันทึกสาเหตุไว้ให้ดูย้อนหลัง
```

ข้อความที่เจ้าของจะได้รับ

```
🛒 ออเดอร์ใหม่ 260807-014
คุณสมหญิง ใจดี · 081-234-5678
หมู่บ้านสุขใจ · รอบเย็น 17:00–19:00
รวม 265 บาท (5 รายการ)
▸ เปิดดูออเดอร์
```

### ความปลอดภัย

- Channel access token และ channel secret เก็บใน environment variable ของ Netlify
  **ไม่เก็บในฐานข้อมูลและไม่อยู่ในโค้ด**
- Webhook ที่ `/api/line/webhook` ตรวจลายเซ็น `X-Line-Signature` ทุกครั้ง ถ้าไม่ตรงทิ้งทันที
- เจ้าของผูกบัญชี LINE ครั้งเดียวโดยพิมพ์รหัสจับคู่ที่ระบบสร้างให้ในหน้าตั้งค่า

## การจัดการรูปภาพ

เจ้าของถ่ายจากมือถือ → บีบอัดในเบราว์เซอร์ก่อนอัปโหลด (ไม่ต้องรอเน็ตอัปโหลดไฟล์ใหญ่)

1. ย่อด้านกว้างเหลือ 800px แปลงเป็น WebP คุณภาพ 0.75 → ประมาณ 40–60KB
2. สร้างรูปย่อ 300px อีกใบ → ประมาณ 12KB ใช้แสดงในการ์ดหน้าแรก
3. เก็บทั้งสองใบใน Firestore (รูปย่ออยู่ในเอกสารสินค้า รูปเต็มแยกเอกสาร)

รูปผัก 100 ชนิดใช้พื้นที่รวมไม่ถึง 10MB จากโควต้าฟรี 1GB
