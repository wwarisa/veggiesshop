# คู่มือนำเว็บขึ้นออนไลน์ (สำหรับคนที่เขียนโค้ดไม่เป็น)

ทำตามทีละขั้น ใช้เวลาประมาณ 40 นาที **ค่าใช้จ่าย 0 บาท/เดือน**
จ่ายอย่างเดียวคือค่าโดเมนตอนพร้อมเปิดจริง (ประมาณ 350–500 บาท/ปี ยังไม่ต้องซื้อตอนนี้ก็ได้)

---

## สิ่งที่ต้องเตรียม

- อีเมล 1 อัน (Gmail ก็ได้)
- คอมพิวเตอร์ 1 เครื่อง (ทำบนมือถือได้แต่ลำบาก)
- เวลาว่างประมาณ 40 นาที

**ไม่ต้องมี**: บัตรเครดิต · ความรู้เรื่องโค้ด · โปรแกรมพิเศษอะไรเลย

---

## ภาพรวม 4 ขั้น

```
ขั้นที่ 1  สมัคร GitHub แล้วเอาโค้ดขึ้นไปเก็บ        ~10 นาที
ขั้นที่ 2  สมัคร Firebase ทำที่เก็บข้อมูล            ~15 นาที
ขั้นที่ 3  สมัคร Netlify แล้วกดเผยแพร่               ~10 นาที
ขั้นที่ 4  ตั้งค่าความปลอดภัยและเปิดใช้งาน            ~5 นาที
```

---

## ขั้นที่ 1 — เอาโค้ดขึ้น GitHub

> ถ้าโค้ดอยู่บน GitHub อยู่แล้ว ข้ามไปขั้นที่ 2 ได้เลย

1. เปิด **github.com** กด **Sign up** สมัครด้วยอีเมล
2. ยืนยันอีเมลตามที่เขาส่งมา
3. เข้ามาแล้วกดปุ่ม **+** มุมขวาบน → **New repository**
4. ตั้งชื่อว่า `veggiesshop` เลือก **Private** (ไม่ให้คนอื่นเห็น)
5. กด **Create repository**
6. ในหน้าที่ขึ้นมา กด **uploading an existing file** แล้วลากไฟล์โปรเจกต์ทั้งหมดเข้าไป
   ⚠️ **ห้ามอัปโหลดโฟลเดอร์ `node_modules` และไฟล์ `.env.local`**
7. กด **Commit changes**

---

## ขั้นที่ 2 — ทำที่เก็บข้อมูลด้วย Firebase

ที่เก็บข้อมูลคือที่ที่เก็บสินค้า ราคา และออเดอร์ทั้งหมด

### 2.1 สร้างโปรเจกต์

1. เปิด **console.firebase.google.com** ล็อกอินด้วยบัญชี Google
2. กด **Create a project** (สร้างโปรเจกต์)
3. ตั้งชื่อ เช่น `veggiesshop` กด **Continue**
4. หน้า Google Analytics — **ปิดสวิตช์** (ไม่ต้องใช้) กด **Create project**
5. รอสักครู่ แล้วกด **Continue**

### 2.2 เปิดฐานข้อมูล Firestore

1. เมนูซ้ายมือ เลือก **Build** → **Firestore Database**
2. กด **Create database**
3. เลือกที่ตั้งเซิร์ฟเวอร์ **asia-southeast1 (Singapore)** — ใกล้ไทยที่สุด เว็บจะเร็ว
4. เลือก **Start in production mode** (โหมดปลอดภัย)
5. กด **Create**

> ⚠️ อย่าเลือก Test mode เด็ดขาด เพราะจะเปิดให้ใครก็อ่านข้อมูลได้

### 2.3 ตั้งกฎความปลอดภัย

1. ในหน้า Firestore กดแท็บ **Rules**
2. ลบข้อความทั้งหมด แล้ววางอันนี้แทน

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // เบราว์เซอร์คุยกับฐานข้อมูลตรงๆ ไม่ได้เลย
    // ทุกอย่างต้องผ่านเซิร์ฟเวอร์ของเว็บเท่านั้น
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

3. กด **Publish**

> นี่คือหัวใจความปลอดภัยของระบบ ต่อให้มีคนรู้ที่อยู่ฐานข้อมูล ก็อ่านหรือแก้อะไรไม่ได้

### 2.4 สร้างกุญแจให้เว็บเข้าฐานข้อมูลได้

1. กดรูปเฟือง ⚙️ มุมซ้ายบน → **Project settings**
2. กดแท็บ **Service accounts**
3. กดปุ่ม **Generate new private key** → **Generate key**
4. ไฟล์ `.json` จะดาวน์โหลดลงเครื่อง **เก็บไว้ให้ดี ห้ามส่งให้ใคร**
5. เปิดไฟล์นั้นด้วย Notepad หรือ TextEdit จะเห็นข้อความประมาณนี้

```json
{
  "project_id": "veggiesshop-xxxxx",
  "private_key": "-----BEGIN PRIVATE KEY-----\nMIIEv...ยาวมาก...\n-----END PRIVATE KEY-----\n",
  "client_email": "firebase-adminsdk-xxxxx@veggiesshop-xxxxx.iam.gserviceaccount.com"
}
```

**จดค่า 3 อันนี้ไว้** จะใช้ในขั้นที่ 3
- `project_id`
- `client_email`
- `private_key` — ต้องคัดลอก **ทั้งก้อน** รวม `-----BEGIN` และ `-----END` และตัว `\n` ทั้งหมด

## ขั้นที่ 3 — เผยแพร่เว็บด้วย Netlify

> ทำไมไม่ใช้ Vercel: แพลนฟรีของ Vercel ระบุว่าใช้ได้เฉพาะงานส่วนตัว ห้ามใช้เชิงพาณิชย์
> ร้านขายผักจริงถือเป็นเชิงพาณิชย์ ส่วน Netlify แพลนฟรีอนุญาตให้ใช้เชิงพาณิชย์ได้

1. เปิด **netlify.com** กด **Sign up** → เลือก **Sign up with GitHub**
2. กดอนุญาตให้ Netlify เข้าถึง GitHub
3. เข้ามาแล้วกด **Add new site** → **Import an existing project**
4. เลือก **GitHub** แล้วเลือก repository `veggiesshop`
5. หน้าตั้งค่า ปล่อยไว้ตามที่เขาเติมให้ (Netlify รู้จัก Next.js อยู่แล้ว)
6. **ยังไม่กด Deploy** — กดที่ **Add environment variables** ก่อน

### ใส่ค่า 4 อันนี้

| ชื่อ (Key) | ค่า (Value) |
|---|---|
| `SESSION_SECRET` | ตัวอักษรสุ่มยาวอย่างน้อย 32 ตัว (ดูวิธีสร้างด้านล่าง) |
| `GOOGLE_CLOUD_PROJECT` | `project_id` จากไฟล์ JSON |
| `FIRESTORE_CLIENT_EMAIL` | `client_email` จากไฟล์ JSON |
| `FIRESTORE_PRIVATE_KEY` | `private_key` จากไฟล์ JSON ทั้งก้อน |

**วิธีสร้าง SESSION_SECRET แบบง่ายที่สุด**
เปิด **passwordsgenerator.net** ตั้งความยาว 40 ตัว ติ๊กให้มีทั้งตัวเลขและตัวอักษร กด Generate แล้วคัดลอกมาใช้

> ⚠️ `FIRESTORE_PRIVATE_KEY` ต้องวางทั้งก้อน ถ้าโปรแกรมตัด `\n` ออกให้พิมพ์กลับเข้าไปด้วย

7. กด **Deploy site** แล้วรอประมาณ 3–5 นาที
8. เสร็จแล้วจะได้ที่อยู่เว็บมา เช่น `random-name-12345.netlify.app`

## ขั้นที่ 4 — เปิดใช้งานครั้งแรก

1. เปิดที่อยู่เว็บที่ได้มา เติม `/admin` ต่อท้าย
2. จะเจอหน้า **เริ่มต้นใช้งานครั้งแรก**
3. **ตั้งรหัส 6 หลักของตัวเอง** — จำให้ดี ใช้ทุกครั้งที่เข้าหน้าจัดการ
4. ติ๊ก **"ใส่ผักตัวอย่างให้ด้วย"** ถ้าอยากได้ผัก 20 อย่างมาลองก่อน
5. กด **เริ่มใช้งาน**

เรียบร้อย! เว็บพร้อมใช้งานแล้ว

## เปลี่ยนชื่อเว็บให้จำง่าย

ที่อยู่ที่ Netlify ให้มาจะสุ่มมา เปลี่ยนได้ฟรี

1. ในหน้า Netlify ของเว็บ กด **Site configuration** → **Change site name**
2. ตั้งชื่อใหม่ เช่น `pak-sod-suksai`
3. ที่อยู่จะกลายเป็น `pak-sod-suksai.netlify.app`

## ใช้โดเมนของตัวเอง (ต้องเสียเงิน)

เมื่อพร้อมเปิดจริงและอยากได้ที่อยู่สั้นๆ เช่น `ผักสดสุขใจ.com`

1. ซื้อโดเมนจาก **z.com/th** หรือ **namecheap.com** (ประมาณ 350–500 บาท/ปี)
2. ในหน้า Netlify กด **Domain management** → **Add a domain**
3. ใส่ชื่อโดเมนที่ซื้อมา แล้วทำตามที่ Netlify บอก (ต้องไปแก้ค่า DNS ที่ผู้ขายโดเมน)
4. รอประมาณ 1–24 ชั่วโมง

> ใบรับรองความปลอดภัย (https) Netlify ทำให้ฟรีอัตโนมัติ ไม่ต้องซื้อเพิ่ม

## ต่อการแจ้งเตือน LINE (ทำทีหลังได้)

> **LINE Notify ปิดบริการถาวรตั้งแต่ 31 มีนาคม 2568** ใช้ไม่ได้แล้ว
> ต้องใช้ LINE Messaging API แทน แพลนฟรีของไทยได้ **500 ข้อความ/เดือน**
> ส่งแค่ "ออเดอร์ใหม่" อย่างเดียว = รับได้ประมาณ 16 ออเดอร์/วัน

1. เปิด **developers.line.biz** ล็อกอินด้วยบัญชี LINE
2. สร้าง **Provider** ใหม่ ตั้งชื่ออะไรก็ได้
3. สร้าง **Channel** แบบ **Messaging API**
4. เข้าไปในแท็บ **Messaging API** กด **Issue** เพื่อสร้าง **Channel access token**
5. แท็บ **Basic settings** จะมี **Channel secret**
6. กลับไปที่ Netlify → **Site configuration** → **Environment variables** เพิ่ม 2 อันนี้

| ชื่อ (Key) | ค่า (Value) |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | Channel access token |
| `LINE_CHANNEL_SECRET` | Channel secret |

7. กด **Deploys** → **Trigger deploy** → **Deploy site** เพื่อให้ค่าใหม่มีผล

## ค่าใช้จ่ายและขีดจำกัดของแพลนฟรี

| บริการ | ฟรีถึงเท่าไหร่ | พอไหมสำหรับร้านผักหมู่บ้าน |
|---|---|---|
| **Firestore** | อ่าน 50,000 / เขียน 20,000 ครั้งต่อวัน · พื้นที่ 1GB | พอมาก ร้านที่มี 50 ออเดอร์/วันใช้ไม่ถึง 5% |
| **Netlify** | แบนด์วิดท์ 100GB/เดือน · build 300 นาที/เดือน | พอมาก |
| **LINE** | 500 ข้อความ/เดือน | ประมาณ 16 ออเดอร์/วัน |

**ไม่ต้องผูกบัตรเครดิตเลยสักที่**

> รูปสินค้าเก็บในฐานข้อมูลโดยตรง (บีบให้เหลือ ~50KB ต่อรูปก่อน) จึงไม่ต้องใช้ Firebase Storage
> ที่ต้องอัปเกรดเป็นแพลนเสียเงิน — รูปผัก 100 ชนิดใช้พื้นที่ไม่ถึง 10MB จากโควต้า 1GB

## ลองใช้ในเครื่องตัวเองก่อน (ไม่ต้องสมัครอะไรเลย)

อยากลองเล่นก่อนตัดสินใจ ทำได้ทันที

```bash
npm install
npm run dev
```

แล้วเปิด `http://localhost:3000` ในเบราว์เซอร์

ระบบจะเก็บข้อมูลเป็นไฟล์ในโฟลเดอร์ `.data/` ในเครื่อง ไม่ต้องมี Firebase
พอใส่ค่า Firestore ใน `.env.local` ครบ ระบบจะสลับไปใช้ Firestore ให้เอง **โดยไม่ต้องแก้โค้ดสักบรรทัด**

## เจอปัญหาตอน deploy

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| **หน้าเว็บขึ้นว่า "ยังตั้งค่าไม่ครบ 1 อย่าง"** | ยังไม่ได้ใส่ `SESSION_SECRET` หรือใส่สั้นเกิน 32 ตัว — ใส่แล้วต้อง Trigger deploy ใหม่ |
| **Build failed** | มักเกิดจากอัปโหลด `node_modules` ขึ้น GitHub ไปด้วย — ลบออกแล้วอัปใหม่ |
| **เข้าเว็บได้แต่ไม่มีสินค้า** | ยังไม่ได้ตั้งค่าครั้งแรก — เข้า `/admin` แล้วตั้งรหัสพร้อมติ๊กใส่ข้อมูลตัวอย่าง |
| **Error เกี่ยวกับ Firestore** | ค่า `FIRESTORE_PRIVATE_KEY` ไม่ครบ — ต้องมี `-----BEGIN PRIVATE KEY-----` และ `-----END PRIVATE KEY-----` ครบทั้งสองอัน |
| **แก้ค่าแล้วไม่มีผล** | ต้องกด Deploys → Trigger deploy → Deploy site ทุกครั้งหลังแก้ค่า |
